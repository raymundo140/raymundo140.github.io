## Overview

Built an embedded tractor-control and telemetry prototype using an STM32 and Raspberry Pi for a John Deere-sponsored systems-on-chip project.

## Architecture

The STM32 handled real-time input acquisition, transmission-model execution, UART communication, and hardware outputs. The Raspberry Pi handled telemetry, logging, visualization, and operator interaction.

The STM32 software was divided into periodic tasks for keypad input, ADC acquisition, transmission-model execution, UART communication, and LCD output.

## Telemetry

The Raspberry Pi received live data over UART, logged it to CSV, and displayed parameters such as throttle, engine speed, vehicle speed, and gear. A Tkinter interface also allowed the operator to command throttle in simulation mode.

## My Contribution — Performance Improvement

The first dashboard implementation coupled serial I/O, logging, and plotting in one path. I reorganized the software with Python threading and a shared queue so data acquisition, storage, and visualization could run independently.

## Result

The final system connected real-time embedded firmware, Linux-based processing, serial communication, operator controls, telemetry logging, and live visualization in one end-to-end prototype.
